## المشكلة

أنت تعمل مع Claude Code. يحتاج إلى تشغيل ترحيل لقاعدة البيانات، أو استدعاء واجهة برمجية، أو الدخول إلى خادم. فيقول:

> «أحتاج كلمة سر قاعدة البيانات — أضفها أنت إلى `.env` وسأكمل.»

وكل طريق من هنا سيّئ:

| ما تفعله | ما الذي يحدث |
|---|---|
| تلصقها في المحادثة | صارت القيمة في السجل، وفي `~/.claude/projects/`، وفي الطلب المُرسَل إلى مزوّد النموذج. إلى الأبد. |
| تضعها في `.env` | الوكيل يقرأ الملف. النتيجة نفسها، إضافةً إلى ملف يُودَع في Git بالخطأ يومًا ما. |
| تشغّل الأمر بنفسك | صرتَ أنت يدَي الوكيل، وضاع سير العمل الذي أردته. |
| تكتبها في الشيفرة «مؤقتًا» | تعرف كيف تنتهي هذه القصة. |

الوكيل محقّ في رفضه استلام السر. لكن «دبّر أمرك بنفسك» ليس سير عمل، ولا أحد يحفظ ثلاثين كلمة سر إنتاجية في ذاكرته.

## الحل

اقسِم بيانات الاعتماد نصفين: الوكيل يأخذ **الاسم**، وأنت تكتب **القيمة**.

</div>

```bash
# الوكيل يشغّل هذا. يُفتح مربّع حوار على جهازك أنت.
vault need DB_PASSWORD

# الوكيل يشغّل هذا. ‎$DB_PASSWORD موجود داخل العملية الابنة وحدها.
vault run DB_PASSWORD -- dotnet ef database update
```

<div dir="rtl">

القيمة لا تمرّ إطلاقًا عبر سياق الوكيل ولا سجلّه ولا طلب الواجهة البرمجية. الوكيل لم يمتلكها قط، فلا يستطيع تسريبها.

## البدء السريع

</div>

```bash
pip install claude-vault        # أو: pipx install claude-vault
vault install-claude            # يثبّت المهارة وخُطّاف الحماية وقواعد المنع
```

<div dir="rtl">

أعد تشغيل Claude Code. هذا كل التثبيت. في المرة القادمة التي يحتاج فيها إلى بيانات اعتماد سيلجأ إلى الخزنة من تلقاء نفسه — فوصف المهارة يُفعَّل عند خطأ 401 و«missing API key» وكل ما تفوح منه رائحة المصادقة.

جرّبه بنفسك:

</div>

```bash
vault need GITHUB_TOKEN                      # يُفتح الحوار، تكتب، انتهى
vault run GITHUB_TOKEN -- gh auth status     # الرمز حاضر، والقيمة محجوبة
vault list                                   # الأسماء فقط، آمن دائمًا
```

## أربع ميزات هي الأهم

### ١. `vault run` — حقن، ثم تنقية للمُخرَجات

تتحوّل الأسرار إلى متغيّرات بيئة لعملية ابنة واحدة. وكل ما تكتبه تلك العملية يُرشَّح في طريق العودة، بما في ذلك الصور التي يتّخذها التسريب فعليًا: الخام، وURL-encoded، وbase64، وJSON-escaped، وحتى حين ينقسم السر بين مخزنَي قراءة.

</div>

```bash
vault run STRIPE_SECRET_KEY -- curl -v https://api.stripe.com/v1/charges
# → Authorization: Bearer ***REDACTED:STRIPE_SECRET_KEY***
```

<div dir="rtl">

هذا الحجب هو بيت القصيد: يستطيع الوكيل تشغيل أوامر مُسهبة وقراءة الأخطاء الحقيقية دون أن يركب السرُّ معها. وإذا اختلف اسم المتغيّر، أعد تعيينه:

</div>

```bash
vault run DB_PASSWORD:ConnectionStrings__Default -- dotnet run
```

<div dir="rtl">

### ٢. `vault need` — الوكيل يسأل، وأنت تجيب خارج القناة

هو الأمر الوحيد المسموح للوكيل باستدعائه ونتيجته وجود بيانات الاعتماد فعلًا. يطبع الأسماء، ويفتح حوارًا لكل ناقص، وينتظر حتى تفرغ، ويخرج بقيمة غير صفرية إن ألغيت. مربّع الحوار ترسمه عملية الخزنة نفسها، فما تطبعه لا يجد طريقًا آخر يسلكه.

</div>

```bash
vault need DB_PASSWORD SMTP_PASSWORD API_TOKEN --with-username
```

<div dir="rtl">

للتكامل المستمر بلا شاشة هناك `vault set NAME --stdin`؛ والطرفية بلا بيئة رسومية تعود إلى سؤال `getpass` مع تأكيد.

### ٣. `vault template` — ملفات إعداد تبقى في Git

السبب الحقيقي لإيداع الأسرار في المستودعات هو أن `appsettings.json` يحتاج واحدًا. أودِع القالب بدلًا منه:

</div>

```jsonc
// appsettings.Development.template.json  ← إيداعه آمن
{ "ConnectionStrings": { "Default": "Server=db;Password=${VAULT:DB_PASSWORD}" } }
```

```bash
vault template appsettings.Development.template.json appsettings.Development.json
```

<div dir="rtl">

يُكتب بأذونات `0600`، وينبّهك إن لم يكن الخرج مُدرجًا في gitignore. ويعمل مع أي صيغة نصية — `.json` و`.yaml` و`.toml` و`.conf` و`.tfvars`. وحين لا تقرأ الأداة سوى dotenv، يكتب `vault env NAME --to .env.local` الملف دون أن يطبعه أبدًا.

### ٤. خُطّاف الحماية — إلزام، لا مجاملة

ملف `SKILL.md` يخبر النموذج بما يفعل. وخُطّاف `PreToolUse` يجعل ذلك واقعًا. يسجّل الأمر `vault install-claude` حارسًا يمنع الأوامر القليلة التي تنقل قيمةً إلى المحادثة:

- `vault get` و`vault env --unsafe-stdout` و`vault run --no-scrub`
- `cat`/`Read` على ملف `.env` أو `master.key` أو `secrets.enc`
- `echo $DB_PASSWORD` و`printenv` وتفريغ البيئة كلها

والاستدعاء الممنوع يعيد تفسيره إلى النموذج، فيصحّح نفسه ويمضي بدل أن يتوقف.

يُدمَج الخُطّاف داخل ملف `settings.json` الموجود لديك — وتبقى خُطّافاتك كما هي — ويفشل مفتوحًا أمام أي مدخل غير متوقّع، لأن حارسًا يُعطِّل سير العمل يُزال، والحارس المُزال لا يحمي شيئًا.

## وأيضًا

**ملفات تعريف** — خزنة واحدة وبيئات عدة:

</div>

```bash
vault --profile prod run DB_PASSWORD -- ./migrate.sh
vault --profile staging list
```

<div dir="rtl">

**ست لغات** في الحوار وسطر الأوامر، مع تخطيط من اليمين إلى اليسار للعربية والفارسية. تُكتشف من إعداد لغة النظام، أو حدّدها بنفسك: `vault lang ar`.

**`vault doctor`** — الواجهة الخلفية، ومسار الخزنة، وتنفيذ keyring، وهل الواجهة الرسومية متاحة، وهل الحارس مثبّت، ومشكلات أذونات الملفات.

**مسار قابل للضبط** — المتغيّر `VAULT_HOME` يضع الخزنة حيث شئت: قرص مُعمّى، أو مجلد مُزامَن، أو مجلد خاص بكل مشروع.

## النموذج الأمني

**التخزين.** مخزن بيانات اعتماد نظام التشغيل متى توفّر (Windows Credential Manager، وmacOS Keychain، وSecret Service). وإلا فملف مُعمّى بخوارزمية AES-256-GCM، يُغلَّف مفتاح بياناته بـ DPAPI على ويندوز، أو يُحفظ في keyring حيث يوجد، أو يُكتب أخيرًا في ملف مفتاح بأذونات `0600` — مع تحذير، لأن هذه الحالة الأخيرة أضعف ومن حقك أن تعرف.

أما الفهرس — الأسماء والأنواع والملاحظات والطوابع الزمنية — فهو JSON صريح عن قصد. الأسماء ليست سرًّا، والوكيل يحتاج إلى قراءتها.

**مِمَّ يحمي:** من دخول بيانات الاعتماد إلى نافذة سياق النموذج، أو سجل المحادثة، أو سجلات المزوّد، أو تاريخ الأوامر، أو إيداع في Git، أو مشاركة شاشة.

**مِمَّ لا يحمي** — بصراحة، لأن أداة أمنية تبالغ في وعودها أسوأ من لا شيء:

- البرمجيات الخبيثة أو أي عملية أخرى تعمل بصلاحياتك. كل ما تستطيع أنت فك تعميته تستطيعه هي.
- برنامج تشغّله بنفسك عن قصد ثم يُسرّب بيئته.
- سرٌّ رآه النموذج **قبل** تثبيت هذه الأداة. غيّر تلك الأسرار.
- وكيل مُصِرّ يملك وصولًا غير مقيّد إلى الصدفة. الخُطّاف يرفع كلفة التسريب، وليس صندوقًا رمليًا.

هذا دفاعٌ في العمق أمام التسريب **العرضي** — وهو التسريب الذي يقع فعلًا.
