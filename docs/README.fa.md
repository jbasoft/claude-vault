## مسئله

با Claude Code کار می‌کنی. باید یک migration اجرا کند، یک API صدا بزند، یا به سروری وصل شود. می‌گوید:

> «رمز دیتابیس را لازم دارم — لطفاً خودت در `.env` بگذار تا ادامه بدهم.»

از این‌جا هر مسیری بد است:

| کاری که می‌کنی | چه اتفاقی می‌افتد |
|---|---|
| در چت paste می‌کنی | مقدار حالا در transcript، در `~/.claude/projects/` و در درخواستی که به ارائه‌دهندهٔ مدل رفته ثبت شده. برای همیشه. |
| در `.env` می‌گذاری | عامل فایل را می‌خواند. همان نتیجه، به‌علاوهٔ فایلی که یک روز اشتباهی commit می‌شود. |
| خودت دستور را اجرا می‌کنی | حالا تو دست‌های عامل شده‌ای. آن جریان کاری که می‌خواستی از بین رفت. |
| «موقتاً» hardcode می‌کنی | خودت می‌دانی آخرش چه می‌شود. |

عامل درست می‌گوید که رمز را نمی‌خواهد. ولی «خودت انجامش بده» یک جریان کاری نیست، و هیچ‌کس ۳۰ رمز production را در حافظه‌اش نگه نمی‌دارد.

## راه‌حل

اعتبارنامه را دو تکه کن: عامل **نام** را می‌گیرد، تو **مقدار** را می‌نویسی.

</div>

```bash
# عامل این را اجرا می‌کند. یک دیالوگ روی دستگاهِ تو باز می‌شود.
vault need DB_PASSWORD

# عامل این را اجرا می‌کند. ‎$DB_PASSWORD فقط داخل پروسهٔ فرزند وجود دارد.
vault run DB_PASSWORD -- dotnet ef database update
```

<div dir="rtl">

مقدار هرگز از context عامل، از transcript یا از درخواست API عبور نمی‌کند. عامل هیچ‌وقت آن را نداشته، پس نمی‌تواند لوش بدهد.

## شروع سریع

</div>

```bash
pip install claude-vault        # یا: pipx install claude-vault
vault install-claude            # اسکیل، هوک محافظ و قواعد deny را نصب می‌کند
```

<div dir="rtl">

Claude Code را دوباره باز کن. کل نصب همین است. دفعهٔ بعد که به اعتبارنامه‌ای نیاز داشته باشد خودش سراغ vault می‌رود — توضیحِ اسکیل روی خطای 401، «missing API key» و هر چیزی که بوی احراز هویت بدهد فعال می‌شود.

خودت امتحانش کن:

</div>

```bash
vault need GITHUB_TOKEN                      # دیالوگ باز می‌شود، می‌نویسی، تمام
vault run GITHUB_TOKEN -- gh auth status     # توکن هست، مقدار redact شده
vault list                                   # فقط نام‌ها، همیشه امن
```

## چهار قابلیتی که مهم‌اند

### ۱. `vault run` — تزریق، بعد پاک‌سازیِ خروجی

اعتبارنامه‌ها برای یک پروسهٔ فرزند تبدیل به متغیر محیطی می‌شوند. هرچه آن پروسه می‌نویسد در راهِ بازگشت فیلتر می‌شود — از جمله شکل‌هایی که نشتی واقعاً به خود می‌گیرد: خام، URL-encoded، base64، JSON-escaped، و حتی وقتی بین دو بافر خواندن تکه‌تکه شده باشد.

</div>

```bash
vault run STRIPE_SECRET_KEY -- curl -v https://api.stripe.com/v1/charges
# → Authorization: Bearer ***REDACTED:STRIPE_SECRET_KEY***
```

<div dir="rtl">

نکتهٔ اصلی همین redact کردن است: عامل می‌تواند دستور verbose اجرا کند و خطای واقعی را بخواند، بدون این‌که رمز هم سوار شود. وقتی نام متغیر فرق دارد، نگاشت کن:

</div>

```bash
vault run DB_PASSWORD:ConnectionStrings__Default -- dotnet run
```

<div dir="rtl">

### ۲. `vault need` — عامل می‌پرسد، تو بیرون از کانال جواب می‌دهی

تنها دستوری که عامل اجازهٔ صدا زدنش را دارد و نتیجه‌اش وجود داشتنِ یک اعتبارنامه است. نام‌ها را چاپ می‌کند، برای هرچه کم است دیالوگ باز می‌کند، تا پایانِ کارِ تو منتظر می‌ماند، و اگر انصراف بدهی با کد غیرصفر خارج می‌شود. دیالوگ را خودِ پروسهٔ vault می‌کشد، پس کلیدهایی که می‌زنی جای دیگری برای رفتن ندارند.

</div>

```bash
vault need DB_PASSWORD SMTP_PASSWORD API_TOKEN --with-username
```

<div dir="rtl">

برای CI بدون نمایشگر `vault set NAME --stdin` هست؛ ترمینالِ بدون محیط گرافیکی به پرسشِ `getpass` با تکرارِ تأیید برمی‌گردد.

### ۳. `vault template` — فایل کانفیگ که در git می‌ماند

دلیل واقعیِ commit شدنِ رمزها این است که `appsettings.json` یکی لازم دارد. به‌جایش قالب را commit کن:

</div>

```jsonc
// appsettings.Development.template.json  ← commit کردنش امن است
{ "ConnectionStrings": { "Default": "Server=db;Password=${VAULT:DB_PASSWORD}" } }
```

```bash
vault template appsettings.Development.template.json appsettings.Development.json
```

<div dir="rtl">

با دسترسی `0600` نوشته می‌شود و اگر خروجی در gitignore نباشد هشدار می‌دهد. برای هر قالب متنی کار می‌کند — `.json`، `.yaml`، `.toml`، `.conf`، `.tfvars`. وقتی ابزاری فقط dotenv می‌خواند، `vault env NAME --to .env.local` فایل را می‌نویسد بدون این‌که هیچ‌وقت چاپش کند.

### ۴. هوکِ محافظ — اجبار، نه ادب

یک `SKILL.md` به مدل می‌گوید چه کار کند. یک هوکِ `PreToolUse` آن را محقق می‌کند. دستور `vault install-claude` محافظی ثبت می‌کند که همان چند دستوری را که مقدار را وارد گفت‌وگو می‌کنند مسدود می‌کند:

- `vault get`، `vault env --unsafe-stdout`، `vault run --no-scrub`
- `cat`/`Read` روی فایل `.env`، `master.key` یا `secrets.enc`
- `echo $DB_PASSWORD`، `printenv`، و dump کردن کل محیط

فراخوانی مسدودشده توضیحش را به مدل برمی‌گرداند، پس مدل خودش را اصلاح می‌کند و ادامه می‌دهد به‌جای این‌که گیر کند.

هوک داخل `settings.json` موجودِ تو ادغام می‌شود — هوک‌های خودت حفظ می‌شوند — و در برابر هر ورودیِ غیرمنتظره fail-open است، چون محافظی که جریان کاری را خراب کند حذف می‌شود، و محافظِ حذف‌شده از هیچ‌چیز محافظت نمی‌کند.

## چیزهای دیگر

**پروفایل‌ها** — یک مخزن، چند محیط:

</div>

```bash
vault --profile prod run DB_PASSWORD -- ./migrate.sh
vault --profile staging list
```

<div dir="rtl">

**شش زبان** در دیالوگ و CLI، با چیدمانِ راست‌به‌چپ برای فارسی و عربی. از locale سیستم تشخیص داده می‌شود، یا خودت تعیین کن: `vault lang fa`.

**`vault doctor`** — backend، مسیر مخزن، پیاده‌سازی keyring، در دسترس بودن رابط گرافیکی، نصب بودن محافظ، و مشکلات دسترسی فایل.

**مسیر قابل تنظیم** — `VAULT_HOME` مخزن را هرجا می‌خواهی می‌گذارد: یک درایو رمزنگاری‌شده، یک پوشهٔ همگام‌شونده، یا یک مسیر جدا برای هر پروژه.

## مدل امنیتی

**ذخیره‌سازی.** هر جا credential store سیستم‌عامل در دسترس باشد از همان استفاده می‌شود (Windows Credential Manager، macOS Keychain، Secret Service). در غیر این صورت یک فایل رمزنگاری‌شده با AES-256-GCM که کلید دادهٔ آن روی ویندوز با DPAPI پوشانده می‌شود، یا در keyring نگه داشته می‌شود، یا در نهایت در یک فایل کلید با دسترسی `0600` نوشته می‌شود — همراه با هشدار، چون آن حالت ضعیف‌تر است و باید بدانی.

فهرست — نام‌ها، نوع‌ها، یادداشت‌ها، زمان‌ها — عمداً JSON ساده است. نام‌ها محرمانه نیستند و عامل باید بتواند بخواندشان.

**در برابر چه چیزی محافظت می‌کند:** ورود اعتبارنامه به context مدل، به transcript چت، به لاگ ارائه‌دهنده، به تاریخچهٔ شل، به یک `git commit`، یا به اشتراک‌گذاری صفحه.

**در برابر چه چیزی محافظت نمی‌کند** — صریح می‌گویم، چون ابزار امنیتی‌ای که بیش از توانش ادعا کند از نبودنش بدتر است:

- بدافزار یا هر پروسهٔ دیگری که با کاربر تو اجرا می‌شود. هرچه تو بتوانی رمزگشایی کنی، آن هم می‌تواند.
- برنامه‌ای که خودت عمداً اجرا می‌کنی و محیط خودش را بیرون می‌فرستد.
- رمزی که مدل **پیش از** نصب این ابزار دیده. آن‌ها را عوض کن.
- عاملی مصمم با دسترسی نامحدود به شل. هوک هزینهٔ نشتی را بالا می‌برد؛ sandbox نیست.

این دفاع در عمق برای نشتیِ **تصادفی** است — همانی که واقعاً اتفاق می‌افتد.

</div>
